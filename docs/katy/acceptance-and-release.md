# Acceptance and release gates

C1 is a source-only foundation. A passing unit suite does not certify a shared draft.

## Before owner-only sandbox installation

- Capture all four current editor files and compare the editor with deployed source.
- Verify both active deployments, owner identity, access settings, manifest and scopes.
- Inventory sheet/property/cache/trigger/mail effects and all external formula refs.
- Finish the universal write-gate fix. Keep mail suppression unconditional for testing.
- Create private source/data backups and restore disposable copies successfully.
- Scan the publication diff for private data; keep all OAuth files outside Git.
- Obtain approval for the exact source commit, Google target and installation method.

The recorded active deployment was owner-only when inspected. No deployment setting
is changed by this branch. `clasp push` and any credential/API setup are outside C1.

## Before a shared coach mock

- Reconcile the full player pool, squads, career games, history and real draft orders.
- Map each tester to authorised team IDs server-side. Test a two-team and three-team
  coach, unknown identities and every Commissioner/President denial boundary.
- Resolve the real capability matrix; do not inherit the demo's broad committee role.
- Separate working/submitted/locked choices, server clock and expected revisions.
- Test two independent sessions and simultaneous requests: one winner for one player,
  no duplicate events on retries, safe stale tabs and reconciliation after reconnect.
- Test date/time boundaries, corrections clearing arming, pause/re-arm/resume, reopen,
  zero retains, 2+2 slots, dynasty evidence, 2–4 delists and own-discard round one.
- Keep taken players searchable with team/pick; crossed-out queues persist until removal.
- Complete a realistic mock with mobile/desktop, interrupted login and repeated buttons.
- Agree date, participants and access before invitations or sharing changes.

Mock-result approval must remain separate from official squad/history publication.
The prepared Apps Script adapter continues to reject `finalize`.

## Before official publication

- Every weekly squad consumer must resolve the same committed release/snapshot.
- Stage changes, verify counts/checksums and reconcile history before the commit pointer.
- Prove rollback for failed writes, failed flush, interrupted publication and retries.
- Verify health status with source, check time and freshness; never claim a live check
  from a saved fixture. Distinguish diagnostic writes from disabled competition writes.
- Present exact commit, passed/failed/not-run tests, migration effect, backup/restore
  evidence, deployment/access settings and rollback for John's release decision.

No live merge/deployment, production write, email or paid model call is authorised
by this source-only stage or by a draft PR.
